# AB#1491977 — Accessibility Enhancement: Migrate to Native HTML `<dialog>`

**Branch:** `rmenner/bugfix/focus-trap-behavior` (bundles the native dialog migration, focus trap implementation, scroll lock rewrite, and backdrop token work)
**Scope:** ~10 files changed across `auro-drawer` core component, floater integration, test suite, and demo pages. Migrated from a custom bib container to a native `<dialog>` element, implemented focus trapping and restoration, rewrote scroll locking, and introduced CSS custom property–based backdrop styling.

---

### Section 1 — The Problem

The `auro-drawer` component used a custom floater bib `<div>` with manually applied `role="dialog"` and `aria-modal` attributes. This approach had several compounding accessibility failures:

- **Focus was not trapped** inside the drawer. Screen reader and keyboard users could tab to content behind the overlay.
- **Focus was not restored** to the trigger element after closing, breaking sequential keyboard navigation.
- **`aria-label` on the drawer bib** was incompatible with iOS VoiceOver, which requires `aria-labelledby` pointing to a real DOM node.
- **Escape key behavior** was inconsistent — it was handled via `keydown` listeners rather than the native `cancel` event, and did not respect modal vs. non-modal context.
- **Scroll locking** relied on overflow manipulation, which did not prevent VoiceOver's three-finger swipe gesture from scrolling content beneath the drawer.

---

### Section 2 — Decision: Migrate to Native `<dialog>`

The core decision was to replace the custom bib container with a native `<dialog>` element and delegate focus trapping, `aria-modal`, and keyboard handling to the browser.

- **Modal drawers** call `showModal()`, which natively traps focus and applies `aria-modal`.
- **Non-modal drawers** call `showPopover()` (with `dialog.show()` as a fallback for browsers without the Popover API) to avoid the native focus trap, allowing interaction with background content as required by WCAG 2.1.2.
- **Nested drawers** call `setAttribute('open', '')` to anchor within the parent container without entering the top layer.
- Manual `role="dialog"` and `aria-modal` attributes were removed — `showModal()` provides these natively.

This decision eliminated an entire category of ARIA-by-hand bugs but introduced timing challenges around animations and focus coordination (see Sections 4 and 5).

---

### Section 3 — `aria-labelledby` Migration and `bibLabel`

`aria-label` on the dialog was replaced with `aria-labelledby` pointing to a visually hidden `<span>` that holds the drawer's label text. This is required for iOS VoiceOver, which does not reliably announce `aria-label` on dialog elements.

A new `bibLabel` property was added to expose the drawer label to the component API. The visually hidden span is rendered inside the `<dialog>` and its `id` is referenced by `aria-labelledby`.

---

### Section 4 — Focus Trap and Restoration Timing

The native `<dialog>` `showModal()` handles the inbound focus trap automatically. The complexity was in **restoring focus on close** correctly:

- The drawer close sequence involves a CSS exit animation (~300ms).
- Focus restoration attempted before the animation completed would either fail silently or restore to a now-hidden element.
- A 350ms delay was introduced for focus restoration to ensure the animation had completed and the trigger element was focusable.

Additional edge cases handled:
- Footer buttons that are `disabled` at close time are skipped; focus falls back to the trigger element.
- When the trigger element itself is removed from the DOM between open and close (e.g., dynamically rendered triggers), focus falls back to `document.body`.

---

### Section 5 — Escape Key Handling via `cancel` Event

Rather than a `keydown` listener intercepting `Escape`, the native `dialog` `cancel` event is now used.

- The `cancel` event only fires for dialogs opened via `showModal()`. The bib always calls `preventDefault()` to suppress native browser close behavior, then re-dispatches as a composed `dialog-cancel` event so `AuroFloater` can decide whether to honour it.
- For **modal drawers**, `AuroFloater` ignores `dialog-cancel`. The close path is controlled exclusively through the close button.
- For **non-modal drawers** (opened via `showPopover()`), Escape is handled natively by the Popover API's built-in light-dismiss. The bib re-dispatches `dialog-cancel` for consistency but it is not the primary Escape path for this mode.
- For **nested drawers** (opened via `setAttribute('open', '')`), Escape is not natively handled; the floater's `dialog-cancel` listener provides the close path.

This replaces a previous `keydown` listener that fired recursively in nested-dialog scenarios (flagged in PR review).

---

### Section 6 — Scroll Lock Rewrite

The previous overflow-based scroll lock did not prevent VoiceOver's three-finger swipe from scrolling the page behind the drawer.

The new implementation uses a `position: fixed` body lock:

```js
// Lock
document.body.style.top = `-${window.scrollY}px`;
document.body.style.position = 'fixed';
document.body.style.width = '100%';

// Unlock — restore scroll position
const scrollY = document.body.style.top;
document.body.style.position = '';
document.body.style.top = '';
window.scrollTo(0, parseInt(scrollY || '0') * -1);
```

This technique prevents all scroll vectors including VoiceOver swipe. Scroll position is captured before locking and restored on close. The scroll lock logic was moved into the floatingUI layer to keep it co-located with show/hide lifecycle management.

---

### Section 7 — Backdrop Migration to CSS Custom Properties

The `::part(drawer-backdrop)` pseudo-element was deprecated in favor of CSS custom property–based styling:

| Token | Default | Purpose |
|---|---|---|
| `--auro-drawer-backdrop-background` | `transparent` | Backdrop fill color |
| `--auro-drawer-backdrop-filter` | — | Backdrop CSS filter (e.g., blur) |

The `dialog::backdrop` pseudo-element is styled using these tokens internally. This approach is more portable than `::part()` because `::backdrop` cannot be targeted through shadow DOM part forwarding — it sits outside the shadow root's styling scope.

---

### Section 8 — Animation Migration: `@starting-style` → `@keyframes`

Entry/exit animations were previously implemented with `@starting-style` transitions. These were replaced with explicit `@keyframes` animations per placement direction (left, right, bottom).

`@starting-style` requires careful ordering of style rules relative to the element's initial render, which conflicted with the `<dialog>` open/close lifecycle — the dialog is hidden (`display: none`) when closed, and `@starting-style` transitions do not fire reliably after `showModal()` in all browsers.

`@keyframes` animations are applied via class toggle and are independent of element insertion timing.

---

### Section 9 — Show/Hide Logic Consolidation

Prior to this work, show and hide logic was distributed across the component, floater, and event handler layers. As part of the migration, show/hide was consolidated into the floater to create a single authoritative path:

- `showBib()` / `hideBib()` are the sole entry points.
- The `<dialog>` `open`/`close` calls, scroll lock, focus trap setup, and animation class toggling all happen inside these methods.
- External callers (trigger clicks, programmatic API) all funnel through the same path.

---

### Section 10 — Three-Path Open Strategy: `showModal` / `showPopover` / `setAttribute`

The final implementation uses three distinct open strategies based on drawer type:

| Drawer type | Open method | Reason |
|---|---|---|
| `modal && !nested` | `showModal()` | Native focus trap, `aria-modal`, top-layer rendering |
| `!modal && !nested` | `showPopover()` (fallback: `dialog.show()`) | No focus trap; Popover API handles Escape and light-dismiss |
| `nested` | `setAttribute('open', '')` | Anchored to parent container; must not enter the top layer |

This split was required because:

- **Escape handling**: `showModal()` fires `cancel` natively; `showPopover()` handles Escape via the Popover API's built-in light-dismiss; `setAttribute('open')` drawers have no native Escape path and rely on the `dialog-cancel` re-dispatch from the bib.
- **Focus trap**: Only modal drawers trap focus. Non-modal and nested drawers allow free keyboard flow to surrounding content (WCAG 2.1.2).
- **Backdrop**: Only `showModal()` renders the native `::backdrop`. Non-modal and nested drawers use a separate `<div class="backdrop">` overlay element for visual backdrop.

### Section 11 — PR Code Review Findings

Sourcery AI flagged three concerns during review:

- **Arbitrary `setTimeout` delays in tests** instead of waiting on lifecycle hooks or observable state. Accepted as a pragmatic workaround for animation timing in unit tests; filed for future hardening.
- **Tests coupled to shadow DOM internals** (querying specific internal element IDs). Acknowledged; left as-is to avoid scope creep in this PR.
- **Hardcoded dates in the keyboard audit demo page** that would become stale. Updated to use dynamic dates.

Copilot flagged several bugs during review:

- `keydown` event handler recursion in nested dialog scenarios → fixed by migrating to the `cancel` event model.
- Nested dialog state management leaving stale open state on parent → fixed in consolidation of show/hide logic.
- Scroll lock styles not restored on abnormal close paths (e.g., programmatic `hideBib`) → fixed by centralizing unlock in `hideBib`.

---

### Key Lessons

1. **Native `<dialog>` + `showModal()` is the correct primitive for modal overlays.** It provides focus trapping, `aria-modal`, and Escape handling for free. The complexity budget shifts from implementing these correctly to managing timing around animations and focus restoration.

2. **`aria-label` on `<dialog>` is not sufficient for iOS VoiceOver.** Use `aria-labelledby` pointing to a real DOM node inside the dialog. A visually hidden `<span>` is the standard pattern.

3. **`position: fixed` body lock is required for full scroll prevention.** `overflow: hidden` on `<body>` does not block VoiceOver's three-finger swipe. Capture `scrollY` before locking and restore it on close.

4. **Focus restoration requires animation awareness.** Restoring focus before a CSS exit animation completes will fail silently or land on a hidden element. Explicit delay or animation event coordination is required.

5. **`::backdrop` cannot be reached via `::part()`.** It lives outside the shadow root. Token-based customization (`--auro-drawer-backdrop-*`) is the correct approach for styling the backdrop from outside the component.

6. **Modal / non-modal / nested is a meaningful three-way split at the API level.** `showModal()`, `showPopover()`, and `setAttribute('open')` have distinct native behaviors (focus trap, top-layer rendering, backdrop, `cancel` event). Treating them as one path leads to layered workarounds — maintain the split explicitly.

7. **Consolidating show/hide into one layer eliminates drift.** When scroll lock, animation, and dialog open/close calls are scattered, partial-execution bugs on edge-case close paths (programmatic close, disconnect, Escape) are inevitable. A single `showBib`/`hideBib` pair is the invariant.
